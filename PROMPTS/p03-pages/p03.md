## PROMPT: Build FastAPI + LangChain Services for Patient Intake, Feedback, and Sentiment

### Goal

Create a production-ready **FastAPI** application with three endpoints:

1. `POST /api/v1/intake` — collect patient details and complaints, invoke a LangChain workflow to generate triage advice (tests + home care vs. urgent visit), **persist advice in MySQL**, and **email** the advice to the patient.
2. `POST /api/v1/feedback` — record patient feedback (unique id, name, gender, religion, review comment).
3. `GET /api/v1/feedback/sentiment/run` — run a LangChain workflow that performs sentiment analysis over all feedback rows, updates each row with `sentiment` and `percentage`, and returns **compact JSON for charting** (counts by sentiment, daily trend, and top words). This API is triggered by an **Admin button** from a PHP MVC screen.

Deliver clean, well-structured code with typing, validation, and tests.

---

### Tech & Libraries

* Python 3.11+
* **FastAPI** + `uvicorn`

### Endpoint Specs

### 1) POST `/api/v1/intake`

**Flow**

1. Validate payload.
2. Upsert patient by `unique_id` (create if not exists; update basic fields).
3. Call `services/triage_chain.py::run_triage(complaints, vitals)` which returns:

   ```
   {
     "advice_category": "HOME_CARE" | "TESTS" | "URGENT_VISIT",
     "test_recommendations": ["CBC","CRP"],
     "home_care_advice": "Hydration, paracetamol 500mg SOS, rest.",
     "urgent_flag": true|false,
     "rationale": "short model explanation text"
   }
   ```
4. Persist an `Intakes` row with all returned fields.
5. Send email to patient if `email` is present. Subject: `Your care advice (Case: {unique_id})`. Body includes advice, tests, and a short disclaimer.
6. Return `IntakeResponse`.

**Responses**

* `201` with `IntakeResponse`
* `400` validation error
* `500` for chain/db/email failures with safe message

### 2) POST `/api/v1/feedback`

**Flow**

1. Validate payload.
2. Insert a `Feedback` row (leave `sentiment`/`percentage` null).
3. Return the created row as `FeedbackOut`.

**Responses**

* `201` with `FeedbackOut`
* `400` validation error

### 3) GET `/api/v1/feedback/sentiment/run`

**Flow**

1. Fetch all feedback rows where `sentiment IS NULL OR percentage IS NULL`.
2. For each, call `services/sentiment_chain.py::analyze(comment)` returning:

   ```
   {"sentiment":"positive|neutral|negative","percentage": float, "keywords": ["wait","staff","polite"]}
   ```
3. Update each row with `sentiment` and `percentage`.
4. Build **chart payloads** in `services/plotting_payload.py`:

   * `summary` counts by sentiment
   * `trend_daily` aggregated by `created_at::date`
   * `top_words` (aggregate keywords across comments)
5. Return `SentimentRunOut` for the PHP Admin UI to plot.

**Responses**

* `200` with `SentimentRunOut`
* `204` if nothing to update (but still return empty structures)
* `500` on failure

### LangChain Workflows

#### `services/triage_chain.py`

* Use an LLM with a **system prompt** that:

  * Reads `complaints` + optional `vitals`.
  * If any red flags (e.g., chest pain + low SpO₂ < 90, very high fever > 40°C, confusion, severe dehydration, severe bleeding), set `advice_category="URGENT_VISIT"`, `urgent_flag=True`, tests minimal, and short safety advice.
  * Else if diagnostics needed, `advice_category="TESTS"` with a concise test list and basic care.
  * Else `advice_category="HOME_CARE"` with clear home instructions.
  * Always be conservative; include **rationale** (not stored, but can be logged).
* Return the dict specified above.
* Make chain easily **mockable** in tests. Allow model via env `OPENAI_API_KEY`; if not set, fall back to a rule-based stub.

#### `services/sentiment_chain.py`

* Small LLM (or rule-based fallback) to output `sentiment` in {positive, neutral, negative} and `percentage` ∈ [0,100].
* Also extract top 3 keywords per comment (lowercase, simple tokenizer; strip stopwords).
